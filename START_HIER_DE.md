## Vorbereitung

Benötigt werden Git, Node.js/npm, Rust mit Cargo und Tauri CLI 2. Auf Linux außerdem die vom Tauri-Projekt benötigten GTK- und WebKitGTK-Entwicklungsbibliotheken. Unter Windows werden die Microsoft-C++-Buildwerkzeuge und WebView2 benötigt. Das Projekt ist nur auf Linux im Build untersucht worden; Windows/macOS benötigen eigene Prüfung.

Im entpackten Projektverzeichnis:

```sh
cd gui
npm ci
cd ../src-tauri
cargo install tauri-cli --version '^2' --locked
cargo tauri dev
```

Für Windows dieselben Befehle in PowerShell ausführen. Der erste Rust-Build lädt zusätzliche Abhängigkeiten, darunter das in `Cargo.lock` referenzierte PicQr-Git-Repository.

Das unten bezeichnete Release enthält die abgenommene Detector-Registry: Sie meldet unbekannte IDs über `Result` statt `Option` und initialisiert eingebaute Handles bei Konflikten atomar und wiederholbar. Das ist eine Änderung der öffentlichen Rust-Signatur; Repository-Aufrufer des Lookup wurden nicht gefunden. Der Backupdialog hat einen Namen und zugeordnete Feldlabels; er beansprucht keine Fokusfalle oder vollständige Modalität. Merkle-Proofs erhalten Grenzen für Position und Tiefe; die zurückgegebene Root stammt aus dem geprüften gespeicherten Header. Header-Sync lehnt widersprechende Forks konservativ ab, vergleicht bei gleicher Höhe den Tip-Hash und behandelt niedrigere Server-Tips als unbestätigt. Ein Aufruf lädt höchstens 2016 Header; eine gültige kürzere Antwort meldet Teilfortschritt und kann fortgesetzt werden. Leere, übergroße oder falsch angeordnete Antworten führen zu Fehlern. Bei einem späteren Headerfehler kann ein bereits gültig gespeicherter Präfix bestehen bleiben. Eine geteilte Store-Referenz und ein Gate begrenzen das Verhalten bei parallelen Aufrufen und Abbruch. Reorg-Auswahl, Schwierigkeitsanpassung, Chainwork-Vergleich und vollständiger Konsens sind damit nicht implementiert; regulärer Wallet-Sync bleibt hinsichtlich Serverangaben nicht unabhängig verifiziert.

## Optionale lokale Agentenschnittstelle

Der Agentenmodus ist standardmäßig aus und wird für jeden Prozess ausdrücklich mit `--agent --data-dir VERZEICHNIS` gestartet. Er hat keinen GUI-Schalter. Die JSON-RPC-Schnittstelle, Beispiele und Sicherheitsgrenzen stehen in [docs/agent-interface.md](docs/agent-interface.md). Für Versuche ein eigenes leeres Datenverzeichnis und ausschließlich Testdaten verwenden. Der aktuelle Lauf enthielt 14 Agententests; das Release wurde zusätzlich ohne Netzwerk lokal geprüft.
